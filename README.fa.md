## فری‌وِن (FreeWhen) چیست؟

هنگامی که گروهی از دوستان قصد دورهمی یا قرار ملاقات دارند، پیشنهادها در تاریخچه چت‌ها گم می‌شوند، هیچ‌کس به درستی نمی‌داند چه کسی با کدام گزینه موافقت کرده، هماهنگی‌ها فرسایشی می‌شوند و معمولاً افرادی که به وسایل نقلیه عمومی وابسته‌اند یا در حاشیه شهر زندگی می‌کنند بیشترین مسافت و سختی رفت‌وآمد را متحمل می‌شوند.

**فری‌وِن (FreeWhen)** این آشفتگی را برطرف می‌کند:

1. **انصاف مبتنی بر شواهد و داده‌ها**: زمان سفر، مسافت پیاده‌روی، تعویض خطوط مترو/اتوبوس، امنیت بازگشت در شب و نیازهای دسترسی‌پذیری فیزیکی برای تک‌تک اعضا محاسبه و لحاظ می‌شود.
2. **موتور محاسباتی قطعی و خالص**: اجرای محاسبات رتبه‌بندی به‌صورت ۱۰۰٪ قطعی، بدون عوارض جانبی شبکه (Zero Side-Effects) و بر پایه ۴ لنز مجزا و شناخته‌شده در نظریه انتخاب اجتماعی.
3. **طراحی بومی برای زبان فارسی و تقویم جلالی**: طراحی‌شده از پایه برای کاربران ایرانی با پشتیبانی کامل از چیدمان راست‌به‌چپ (RTL)، تقویم هجری شمسی، تایپوگرافی فارسی و شبکه حمل‌ونقل شهری ایران.
4. **ورود بدون اصطکاک و بی‌نیاز از نصب**: شرکت‌کنندگان می‌توانند تنها با کلیک روی یک پیوند دعوت (`/e/:token`) در مرورگر وب و بدون نیاز به نصب اپلیکیشن یا ساخت حساب کاربری، وضعیت حضور خود را اعلام کنند.
5. **حفظ حریم خصوصی از پایه**: مختصات جغرافیایی به ۲ رقم اعشار (دقت تقریبی حدود ۱.۱ کیلومتر) گرد می‌شوند، ردیابی موقعیت مکانی در پس‌زمینه کاملاً ممنوع است و گیت‌های خودکار از نشت اطلاعات حساس جلوگیری می‌کنند.

> **نکته**: فری‌وِن از هر دو معماری بک‌اند مبتنی بر **Supabase** و بک‌اند کاملاً مستقل **PostgreSQL محلی + PostgREST** پشتیبانی می‌کند (`docker-compose.local.yml`). جابه‌جایی بین این دو تنها با تغییر متغیر محیطی `DATABASE_BACKEND` انجام شده و نیازی به کوچک‌ترین تغییر در کد کلاینت ندارد.

## ویژگی‌های کلیدی

- **چهار لنز تصمیم‌گیری شفاف**: مدل‌های شفاف تصمیم‌گیری بر اساس قضایای انتخاب اجتماعی ارو (**متوازن (Balanced)**، **سریع‌ترین (Fastest)**، **عادلانه‌ترین (Fairest)** و **اقتصادی‌ترین (Cheapest)**).
- **نردبان تنزل تدریجی ارائه‌دهندگان مسیریابی (Degradation Ladder)**: زنجیره مقاوم استعلام ماتریس سفر: `ماتریس نشان` ← `مسیریابی نشان` ← `OpenRouteService` ← `فاصله خط مستقیم (Haversine)`.
- **دسترسی‌پذیری با منطق سه‌ارزشی (Tri-State)**: وضعیت دسترسی ویلچر و ورودی بدون پله با سه مقدار مشخص (`confirmed_yes`: تأییدشده دارد، `confirmed_no`: فاقد دسترسی، `unknown`: نامشخص). داده غایب هرگز به‌اشتباه دسترسی‌پذیر تلقی نمی‌شود.
- **دوزبانه و RTL-First**: پشتیبانی کامل از فارسی و انگلیسی، تبدیل خودکار ارقام به فارسی، قالب‌های بومی‌سازی‌شده دلایل رتبه‌بندی و تشخیص خودکار جهت متن.
- **معماری دوگانه بک‌اند (Dual Backend)**: هماهنگی کامل میان پلتفرم ابری Supabase و پشته مستقل محلی (PostgreSQL 15 + PostgREST 12 + سرویس توکن و پل وب‌سوکت Node.js).
- **گیت‌های اعتبارسنجی هفت‌گانه امنیتی**: هفت گیت اعتبارسنجی خودکار قبل از کامیت و بیلد (`npm run gate:all`) که از نشت کلیدهای سرور، ثبت اطلاعات محرمانه در لاگ‌ها و به‌کارگیری استایل‌های هاردکدشده جلوگیری می‌کنند.
- **امکان بررسی آنی بدون نصب**: ایجاد خروجی مستقل وب ایستا (`npm run export:web`) جهت دسترسی سریع کاربران و بازبین‌ها در مرورگرهای موبایل و دسکتاپ.

## راهنماها

دو راهنما، هر دو خودکفا: **توسعه محلی** برای اجرای کامل روی سیستم خودتان، و
**استقرار** برای انتشار. بقیه این فایل توضیح می‌دهد که فری‌وِن *چگونه کار می‌کند*؛
این دو بخش توضیح می‌دهند که *چگونه آن را اجرا کنید*.

### راهنمای ۱ — توسعه محلی

اجرای کل سیستم به‌صورت محلی: پایگاه داده، API و اپلیکیشن. بدون نیاز به حساب ابری،
حساب Expo یا سرویس بیلد.

#### پیش‌نیازها

| نیازمندی | نسخه | برای چه کاری |
|---|---|---|
| **Node.js** | ۲۲.۱۳ یا بالاتر | همه بخش‌ها |
| **Docker** | نسخه‌ای نسبتاً جدید | PostgreSQL و PostgREST با Compose |
| **Java JDK** | ۱۷ | بیلد اندروید |
| **Android Studio** | نسخه‌ای نسبتاً جدید | شبیه‌ساز اندروید |
| **Xcode** | نسخه‌ای نسبتاً جدید | بیلد iOS — فقط macOS |

#### گام ۱ — نصب و تنظیمات

```bash
git clone https://github.com/IMROVOID/FreeWhen.git
cd FreeWhen
npm install
cp .env.example .env
```

متغیرهای عمومی کلاینت را در فایل `.env` وارد کنید:

```ini
EXPO_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-supabase-anon-key
EXPO_PUBLIC_APP_BASE_URL=http://127.0.0.1:8081
```

متغیرهای سمت سرور (که هرگز در باندل قرار نمی‌گیرند) در بخش
[متغیرهای محیطی](#متغیرهای-محیطی) توضیح داده شده‌اند.

#### گام ۲ — راه‌اندازی پایگاه داده

این دستور PostgreSQL 15 و PostgREST 12 را در کانتینر اجرا می‌کند، سپس اسکیمای
پروژه را اعمال و رویداد آزمایشی که مسیر `/start` به آن اشاره دارد را مقداردهی اولیه
می‌کند.

```bash
npm run db:local:up           # PostgreSQL و PostgREST با docker-compose
npm run db:migrate            # افزایشی و تکرارپذیر
npm run db:seed               # رویداد آزمایشی که /start می‌خواند
```

برای استفاده از استک Supabase خودمیزبان به‌جای استک محلی، مقدار
`DATABASE_BACKEND=supabase` را قرار دهید. API و کلاینت در هر دو حالت بدون تغییر
کار می‌کنند — به بخش
[معماری دوگانه بک‌اند و همگام‌سازی بلادرنگ](#معماری-دوگانه-بک‌اند-و-همگامسازی-بلادرنگ)
مراجعه کنید.

#### گام ۳ — شروع API

```bash
npm run server                # API روی 127.0.0.1:8787
```

دو سرویس اختیاری بلندمدت، هر کدام در یک ترمینال مستقل، برای بک‌اند محلی:

```bash
npm run server:auth           # احراز هویت و صدور توکن (پورت 8789)
npm run server:realtime       # پل وب‌سوکت تغییرات بلادرنگ (پورت 8788)
```

پل بلادرنگ اختیاری است: بدون آن، صفحه تصمیم‌گیری به نظرسنجی ۱۰ ثانیه‌ای برمی‌گردد
— همان چیزی که هر استقرار بدون سوکت دریافت می‌کند.

#### گام ۴ — اجرای اپلیکیشن

```bash
npm start                     # باندلر Expo Metro
npm run android               # یا: اجرا روی شبیه‌ساز / دستگاه
```

برای iOS (فقط macOS):

```bash
npx expo prebuild --platform ios
npm run ios
```

> **حساب کاربری Expo لازم نیست.** بیلد فری‌وِن به‌صورت کاملاً محلی با
> `npx expo run:android` انجام می‌شود و به سرویس بیلد ابری وابسته نیست.

#### گام ۵ — اجرای نسخه وب به‌صورت محلی

همان اپلیکیشن به یک باندل ایستا خروجی می‌گیرد:

```bash
npm run export:web            # ساخت بسته وب ایستا در dist/
npm run gate:web              # بررسی نشت اطلاعات محرمانه در dist/
npx serve dist -l 8081        # http://localhost:8081
```

بسته خروجی با چیدمان راست‌به‌چپ (`dir="rtl"`)، فراداده فارسی و تنظیمات viewport
از پیش آماده است.

#### اعتبارسنجی پروژه پیش از اعتماد به آن

```bash
npm run typecheck && npm run lint
npm test                      # مجموعه تست‌های واحد و کامپوننت‌ها
npm run test:engine           # تست‌های موتور بر اساس نام
npm run test:db               # روی PostgreSQL در حال اجرا
npm run gate:all              # هفت گیت انتشار
```

> **یک نکته که دردسرساز می‌شود.** دستور `npm install` در ویندوز می‌تواند فایل
> `app.json` و مانیفست را از پروژه نیتیو ناهمگام کند و اپلیکیشن نصب‌شده تلاش کند
> جاوااسکریپت را از Metro بارگذاری کند. اگر پیام *"Unable to load script"* روی
> دستگاه ظاهر شد، دستور `adb reverse tcp:8081 tcp:8081` را اجرا و Metro را
> دوباره راه‌اندازی کنید — این اپلیکیشن یک بیلد توسعه است، نه نسخه نهایی.

### راهنمای ۲ — استقرار

یک سرور، یک اپراتور، بدون خط لوله CI و بدون سرویس بیلد ابری — به‌صورت آگاهانه.
هر گام زیر یک اسکریپت است تا فرآیند *تکرارپذیر* باشد، نه چیزی که باید به خاطر سپرده
شود.

#### گام ۱ — بک‌اند

استک Supabase (پیش‌فرض) یا بک‌اند مستقل PostgreSQL + PostgREST را با انتخاب
`DATABASE_BACKEND` اجرا کنید. مایگریشن‌ها را با `npm run db:migrate` اعمال کنید —
افزایشی و تکرارپذیر هستند.

API می‌تواند به‌صورت یک پراسس بلندمدت Node اجرا شود (`npm run server`) یا روی یک
زمان اجرای درخواست/پاسخ مستقر شود. فایل `server/runtime/README.md` همه قراردادهای
فراخوانی پشتیبانی‌شده و فایل ورودی هر کدام را فهرست می‌کند؛ انتقال پایگاه داده با
`DATABASE_BACKEND` انتخاب می‌شود (روی سوکت، یا روی HTTPS بدون سوکت).

#### گام ۲ — ساخت خروجی وب

```bash
EXPO_PUBLIC_DEMO_TOKEN=freewhen-test-invite-token EXPO_PUBLIC_APP_BASE_URL=https://your-host npm run build:web
```

اسکریپت `scripts/build/export-web.sh` مراحل *گیت‌های منبع ← خروجی ← `gate:web` ←
بررسی نهایی* را به همین ترتیب اجرا می‌کند. سه نکته حیاتی است:

- **گزینه `--clear` اختیاری نیست.** پوشه کهنه `dist/` چانک‌های هش‌شده بیلد قبلی را
  نگه می‌دارد در حالی که `index.html` جدید به چانک‌های دیگری اشاره می‌کند — صفحه
  محلی کار می‌کند و روی سرور ۴۰۴ می‌دهد.
- **مقادیر `EXPO_PUBLIC_*` در زمان خروجی درون‌ریزی می‌شوند، نه در زمان اجرا.** توکن
  آزمایشی باید در شل بیلد باشد، نه فقط روی سرور. دقیقاً به همین دلیل `gate:web`
  خروجی را اسکن می‌کند و نه منبع را.
- **پوشه `web/` با `dist/` ادغام نمی‌شود.** مسیریابی سمت کلاینت اپلیکیشن مسیرهای
  `/dl/` و `/privacy` را پنهان می‌کند؛ این دو ریشه ایستای جداگانه‌اند تا با هم
  تداخل نداشته باشند.

#### گام ۳ — ساخت فایل APK اندروید

```bash
export FREE_WHEN_RELEASE_STORE_FILE=/secure/freewhen-release.keystore
export FREE_WHEN_RELEASE_STORE_PASSWORD=…
npm run build:apk
```

اسکریپت `scripts/build/build-apk.sh` دستور `npx expo prebuild --platform android` و
سپس `./gradlew assembleRelease` را اجرا می‌کند و نتیجه را در
`web/dl/freewhen.apk` کپی می‌کند.

##### کلید امضا (Keystore)

**آن را نگه دارید و محلش را ثبت کنید.** یک بار و خارج از مخزن بسازید:

```bash
keytool -genkeypair -v -keystore freewhen-release.keystore   -alias freewhen -keyalg RSA -keysize 2048 -validity 10000
```

اندروید به‌روزرسانی امضاشده با کلید متفاوت را رد می‌کند، بدون هیچ پیام خطای
توضیح‌دهنده‌ای. اگر فایل گم شود، هر بیلد آینده یک *اپلیکیشن جدید* خواهد بود که
روی نسخه نصب‌شده روی گوشی شرکت‌کننده‌ها نصب نمی‌شود. اسکریپت بیلد در صورت تنظیم
نبودن `FREE_WHEN_RELEASE_STORE_FILE` **با خطا متوقف می‌شود** تا هرگز یک خروجی
امضانشده که شبیه موفقیت است تولید نکند.

> **محل کلید امضا برای این استقرار:** `______________________` (هنگام آماده‌سازی
> سرور تکمیل شود؛ نباید داخل مخزن باشد و نباید تنها نسخه موجود باشد).

#### گام ۴ — انتشار

Caddy پوشه `dist/` را به‌عنوان اپلیکیشن و `web/` را به‌عنوان یک ریشه ایستای
جداگانه سرو می‌کند، تا مسیریابی سمت کلاینت نتواند مسیرهای `/dl/` یا `/privacy` را
پنهان کند.

```bash
DEPLOY_HOST=deploy@your-host DEPLOY_BASE_URL=https://your-host EXPO_PUBLIC_DEMO_TOKEN=freewhen-test-invite-token npm run deploy
```

اسکریپت `scripts/deploy/deploy.sh` مراحل *گیت‌ها ← خروجی ← `gate:web` ← rsync ←
مایگریشن ← بارگذاری مجدد Caddy ← تست دود* را اجرا می‌کند. **ترتیب، خودِ تضمین
امنیت است**: جابه‌جا کردن `rsync` به بالای `gate:web` خروجی‌ای را منتشر می‌کند که
هرگز اسکن نشده، و این تنها تغییری است که هرگز نباید به این اسکریپت داده شود. یک
تست، ترتیب خطوط را تضمین می‌کند.

تست دود همه مسیرهای سروشده *و* همه مسیرهای ردشده را بررسی می‌کند. مهم‌ترین حالت
این است که مسیری که باید رد شود، `200` برگرداند — یعنی `/studio`، سرویس حذف‌شده یا
source map به‌صورت عمومی قابل دسترسی است:

```
/health  /start  /privacy  /dl/  /dl/freewhen.apk  /api/health   → 200
/studio  /storage/v1/*  /functions/v1/*  *.map                    → 404
```

#### گام ۵ — بررسی مسیر `/start`

آدرس منتشرشده را باز کنید: فهرست رتبه‌بندی‌شده، تعویض لنز، تفکیک سفر هر نفر برای یک
مکان، دکمه تأیید نهایی، و کارت یکسان در مرورگر دوم. همه این‌ها باید **بدون حساب
کاربری و بدون نصب** بارگذاری شوند.

#### بازگشت به نسخه قبل (Rollback)

| سناریو | اقدام | زمان |
|---|---|---|
| انتشار باگ در اپلیکیشن | بیلد مجدد APK و جایگزینی `/dl/freewhen.apk` | چند دقیقه |
| **باگ در وب** | خروجی مجدد (`--clear`) و rsync پوشه `dist/` | **چند دقیقه، بدون بازبینی** |
| باگ در بک‌اند | استقرار تصویر قبلی؛ مایگریشن‌ها افزایشی هستند | چند دقیقه |
| آسیب داده در مایگریشن | بازیابی از `pg_dump` شبانه | حدود یک ساعت |
| عدم دسترسی به سرور | سرور جایگزین؛ APKهای نصب‌شده همچنان کار می‌کنند | — |

مسیر بیلد محلی **همان** استراتژی بازگشت است: یک اصلاح فقط-JavaScript در همان روز
به بازبین می‌رسد، بدون نیاز به بیلد مجدد APK.

> **پشتیبان‌گیری شبانه:** `pg_dump` به یک محل دوم. داده‌های آزمایشی کم‌حجم هستند؛
> از دست رفتن پایگاه داده در میانه تست در چند دقیقه قابل بازیابی است.

#### تحلیل و آمار (Analytics)

به‌صورت خودمیزبان در جدول `analytics_event`. **بدون سرویس تحلیل شخص ثالث** —
دسترسی‌پذیری از ایران تأیید نشده است و یک نقطه پایش که درخواست را مسدود کند بدتر
از نبود پایش است.

```bash
npm run db:query -- "select name, count(*) from analytics_event group by name"
```

قیف (`server/lib/analytics.ts`) هفت گام را ثبت می‌کند:
`invite_link_opened` ← `guest_joined` ← `start_point_set` ← `proposal_created` ←
`vote_cast` ← `decision_confirmed` ← `rsvp_changed`. گام‌های ۲ تا ۵ قیف جذب
کاربر هستند.

پاک‌سازی دو لایه است، به‌صورت آگاهانه: تابع `track()` هر داده را از
`redactObject()` عبور می‌دهد، و یک تریگر پایگاه داده هر INSERT را که کلید
هم‌شکل با مختصات داشته باشد رد می‌کند. یک لایه فقط تا زمانی دوام می‌آورد که هر
نویسنده آینده آن را به خاطر بسپارد.

## موتور تصمیم‌گیری و لنزهای امتیازدهی

بر اساس قضیه عدم امکان ارو، هیچ قاعده تجمیع واحدی وجود ندارد که به طور هم‌زمان تمامی اصول عدالت را برآورده کند. به همین دلیل، فری‌وِن ۴ لنز مشخص، شفاف و قابل انتخاب ارائه می‌دهد:

| لنز تصمیم‌گیری | قاعده بهینه‌سازی | مدل انتخاب اجتماعی | وضعیت برنده شاخص |
|---|---|---|---|
| **متوازن (Balanced)** | `argmax lexicographic (floor, mean)` | بیشینه‌سازی کف راولز + فایده‌گرایی | بیشینه‌سازی مطلوبیت برای فردی که سخت‌ترین مسیر را دارد؛ تفکیک تساوی با میانگین کل (پیش‌فرض). |
| **سریع‌ترین (Fastest)** | `argmin totalTime` | فایده‌گرایی بنتام | کمینه‌سازی مجموع کل دقایق رفت‌وآمد همه افراد گروه. |
| **عادلانه‌ترین (Fairest)** | `argmin gap` *(دارای سقف محافظ)* | برابری‌خواهی / کمترین اختلاف | کمینه‌سازی فاصله میان دورترین و نزدیک‌ترین فرد، مشروط بر حفظ کف کیفیت (جلوگیری از محرومیت همگانی). |
| **اقتصادی‌ترین (Cheapest)** | `argmin totalCost` | بهره‌وری اقتصادی و مالی | کمینه‌سازی مجموع هزینه‌های سفر و پارکینگ بر حسب ریال/تومان. هزینه‌های مجهول هرگز رایگان فرض نمی‌شوند. |

### قالب‌های دلایل و توضیحات بومی‌سازی‌شده

موتور رتبه‌بندی هرگز متن‌های ثابت رشته‌ای صادر نمی‌کند. در عوض، شناسه قالب همراه با پارامترهای عددی بازگردانده شده و کلاینت بر اساس زبان فعال کاربر آن را ترجمه و اعداد را قالب‌بندی می‌کند:

| شناسه قالب | پارامترها | توضیح کاربردی |
|---|---|---|
| `balanced_headline` | `{ floorMinutes, meanMinutes }` | نمایش زمان سفر فرد در دورترین وضعیت به همراه میانگین گروه. |
| `fastest_headline` | `{ totalMinutes }` | مجموع کل زمان رفت‌وآمد همه اعضای گروه. |
| `fairest_headline` | `{ gapMinutes, floorMinutes }` | حداقل اختلاف زمان سفر با حفظ کف آستانه رضایت. |
| `cheapest_headline` | `{ totalCostIrr }` | برآورد کل هزینه مالی ایاب‌وذهاب و پارکینگ گروه. |
| `coverage_missing` | `{ missingCount }` | اعلام تعداد افرادی که هنوز موقعیت مکانی خود را مشخص نکرده‌اند. |
| `low_confidence` | `—` | هشدار اتکای برخی محاسبات بر تخمین خط مستقیم به جای نقشه زنده. |
| `excluded_filter` | `{ venueName, reason }` | دلیل حذف مکان‌های نامناسب (بسته بودن در ساعت قرار، عدم دسترسی بدون پله و...). |

## راهنماهای پیشرفته

### محاسبات ریاضی انصاف و مطلوبیت سفر

فری‌وِن محاسبات سفر تک‌تک اعضا را به یک شاخص مطلوبیت نرمال‌شده در بازه `[۰, ۱۰۰]` تبدیل می‌کند:

$$\text{utility}(t) = \max\left(0, 100 \cdot \left(1 - \frac{t}{T_{\text{max}}}\right)\right)$$

که در آن $t$ دقایق مؤثر سفر (شامل زمان تردد، پیاده‌روی، تعویض وسیله و ضریب شب) و $T_{\text{max}}$ سقف بودجه زمانی هر شرکت‌کننده است (پیش‌فرض ۹۰ دقیقه).

1. **جریمه سفر در شب (Night Penalty)**: اگر رویداد در شب برگزار شود و فرد گزینه `avoidsNightTravel` را فعال کرده باشد، زمان سفر با ضریب ۱.۳۵ برآورد می‌شود.
2. **ضریب انحراف حمل‌ونقل عمومی (Transit Detour)**: در شرایط عدم دسترسی به ماتریس آنلاین وسایل نقلیه عمومی، فاصله مستقیم بر اساس شبکه شهری تهران با ضریب ۱.۴ و سرعت متوسط ۲۲ کیلومتر در ساعت محاسبه می‌شود.
3. **دقت کامل تا گام نهایی**: محاسبات اعشاری با دقت ۶۴ بیت ذخیره شده و عملیات گرد کردن به دو رقم اعشار صرفاً یک‌بار و در خروجی نهایی انجام می‌گیرد (`round2`).

### معماری دوگانه بک‌اند و همگام‌سازی بلادرنگ

فری‌وِن استقلال کامل از سرویس‌های ابری را از طریق امکان جابه‌جایی آنی میان دو ساختار تضمین می‌کند:

```
┌────────────────────────────────────────────────────────┐
│                   کلاینت فری‌وِن                        │
│            (نسخه وب / اندروید / آی‌او‌اس)               │
└──────────────────────────┬─────────────────────────────┘
                           │
             متغیر DATABASE_BACKEND
             ┌─────────────┴─────────────┐
             ▼                           ▼
 ┌───────────────────────┐   ┌───────────────────────┐
 │     بک‌اند Supabase    │   │  بک‌اند مستقل محلی   │
 │  - سرویس GoTrue       │   │  - سرویس توکن: 8789   │
 │  - واسط PostgREST     │   │  - PostgREST: 3000    │
 │  - سیستم CDC بلادرنگ  │   │  - وب‌سوکت: 8788      │
 └───────────────────────┘   └───────────────────────┘
```

- **احراز هویت**: توکن‌های استاندارد HS256 با شناسه `role: authenticated` و مشخصه `is_anonymous: true` بدون اخذ شماره یا ایمیل صادر می‌شوند.
- **پل ارتباطی بلادرنگ**: در حالت بک‌اند محلی، دستور `NOTIFY event_changes` در پایگاه داده موجب انتشار آنی وقایع از طریق کانال‌های تفکیک‌شده وب‌سوکت به شرکت‌کنندگان رویداد می‌شود.

## توسعه و تست

### گیت‌های کیفیت و اعتبارسنجی انتشار

کلیه گیت‌های هفت‌گانه باید با موفقیت کامل (`exit 0`) پیش از ادغام کدها یا استقرار برنامه اجرا شوند:

```bash
npm run gate:all
```

| اسکریپت گیت | دستور اجرا | هدف و دامنه بررسی |
|---|---|---|
| `gate:secrets` | `npm run gate:secrets` | پویش فایل‌های منبع جهت اطمینان از عدم وجود کلیدهای محرمانه سرور. |
| `gate:location` | `npm run gate:location` | ممانعت از اعلان دسترسی به موقعیت مکانی در پس‌زمینه در مانیفست‌ها. |
| `gate:engine-purity` | `npm run gate:engine-purity` | تضمین عدم وابستگی پوشه `src/engine/` به ری‌اکت نیتیو، اکسپو یا عملیات I/O. |
| `gate:logs` | `npm run gate:logs` | اطمینان از عبور تمامی خروجی‌های لاگ از فیلترهای پالایش داده‌های حساس. |
| `gate:design` | `npm run gate:design` | جلوگیری از به‌کارگیری رنگ‌ها و فاصله‌های هاردکدشده به جای توکن‌های تم. |
| `gate:i18n` | `npm run gate:i18n` | تضمین همخوانی و انطباق ۱۰۰٪ کلیدهای فایل‌های `fa.json` و `en.json`. |
| `gate:web` | `npm run gate:web` | ممیزی پوشه خروجی وب `dist/` از نظر عدم نشت اطلاعات سرور. |

### مجموعه‌های تست خودکار

```bash
# اجرای بیش از ۴۰۰ تست واحد و آزمون‌های یکپارچگی
npm test

# اجرای تست‌ها به تفکیک ماژول
npm test -- jalali
npm test -- engine

# اجرای تست‌های اعتبارسنجی موتور سنجش عدالت
npm run test:engine

# اجرای تست‌های پایگاه داده و سیاست‌های امنیتی RLS (نیازمند داکر محلی)
npm run test:db
```

### ایجاد خروجی‌های نهایی

#### بیلد بسته اندروید (APK) به صورت محلی

```bash
# ایجاد ساختار کدهای بومی اندروید
npx expo prebuild --platform android

# ساخت فایل APK اشکال‌زدایی
npm run android
```

#### ساخت بسته نسخه وب

```bash
# کامپایل بسته ایستا

npm run gate:web
```

خروجی‌های کامپایل‌شده در پوشه `dist/` قرار می‌گیرند و آماده بارگذاری بر روی سرورهای وب یا CDN هستند.

## مشارکت در پروژه

از مشارکت توسعه‌دهندگان در پروژه فری‌وِن استقبال می‌کنیم. جهت حفظ کیفیت و استانداردهای معماری پروژه، لطفاً به این موارد توجه فرمایید:

### فرآیند توسعه

1. **انشعاب و شاخه‌بندی**: یک شاخه جدید با نام معنادار ایجاد کنید (مانند `feat/decision-cards` یا `fix/jalali-leap-year`).
2. **رعایت توسعه آزمون‌محور (TDD)**:
   - ابتدا یک تست بنویسید که رفتار جدید را بررسی کرده و در حال حاضر رد شود (Red).
   - حداقل کد تمیز لازم برای قبولی تست را پیاده‌سازی کنید (Green).
   - ساختار کد را با حفظ قبولی آزمون‌ها بازآفرینی و مرتب کنید (Refactor).
3. **حفظ ماژولاریتی و استقلال کدها**:
   - فایل‌ها را ترجیحاً زیر ۳۰۰ سطر نگه دارید.
   - جهت وابستگی‌ها باید همواره یک‌سویه باشد (`components` ← `features/hooks` ← `engine/lib` ← `types`).
   - کدهای موتور تصمیم‌گیری در `src/engine/` باید ۱۰۰٪ خالص و قطعی بمانند.
4. **رعایت توکن‌های طراحی**:
   - هرگز از کدهای رنگی مستقیم مانند هگز یا مقادیر عددی برای فاصله‌ها استفاده نکنید و از توکن‌های تم بهره بگیرید.
5. **اجرای گیت‌ها قبل از ارسال کامیت**:
   ```bash
   npm run typecheck
   npm run lint
   npm test
   npm run gate:all
   ```
6. **ارسال درخواست ادغام (Pull Request)**: توضیحات شفاف درباره تغییرات اعمال‌شده و شواهد قبولی تست‌ها را در PR قید نمایید.

## سلب مسئولیت و ملاحظات قانونی

> **مهم**: لطفاً پیش از استقرار یا استفاده از نرم‌افزار، این بیانیه را به دقت مطالعه فرمایید.

1. **هدف آموزشی و عام‌المنفعه**: فری‌وِن یک پروژه متن‌باز است که به منظور تسهیل هماهنگی‌های گروهی و پیاده‌سازی الگوهای ریاضی عدالت توزیعی ایجاد شده است.
2. **حفظ حریم خصوصی موقعیت مکانی**: فری‌وِن مختصات جغرافیایی دریافتی را تا ۲ رقم اعشار (دقت تقریبی ۱.۱ کیلومتر) گرد کرده و موقعیت‌های مکانی را فقط در طول فرآیند فعال هماهنگی در حافظه نگه می‌دارد. این سامانه هیچ‌گونه رهگیری در پس‌زمینه یا ثبت تاریخچه حرکتی کاربران انجام نمی‌دهد.
3. **سرویس‌های شخص ثالث**: فری‌وِن با وب‌سرویس‌های ارائه‌دهنده نقشه و مسیریابی (مانند نشان، مپ‌باکس و OpenRouteService) در ارتباط است. کاربران موظف به رعایت شرایط استفاده این سرویس‌ها هستند و فری‌وِن مسئولیتی در قبال محدودیت سهمیه (Quota)، اختلالات مقطعی سرویس‌ها یا خطای داده‌های نقشه ندارد.
4. **عدم تضمین و ارائه نرم‌افزار به صورت وضعیت موجود**: این نرم‌افزار به صورت «وضعیت موجود» (AS IS) و بدون هرگونه ضمانت صریح یا ضمنی ارائه می‌شود. توسعه‌دهندگان مسئولیتی در قبال تأخیرهای ترافیکی، تغییر نرخ کرایه‌ها، لغو قرارها یا اشتباهات زمانی نمی‌پذیرند.
5. **حقوق علائم تجاری**: کلیه نام‌ها، نشان‌ها و علائم تجاری (شامل «نشان»، «مپ‌باکس»، «اکسپو»، «ری‌اکت نیتیو»، «پستگرس‌کیوال» و «سوپابیس») متعلق به دارندگان قانونی آنهاست. فری‌وِن پروژه‌ای مستقل بوده و به هیچ‌یک از این سازمان‌ها وابسته نیست.
